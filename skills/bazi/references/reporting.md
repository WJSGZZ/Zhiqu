## 一、交付选择

- 完整命盘默认生成单文件交互式 HTML：可点击展开大运、流年与证据链，可搜索，可直接打印为 PDF。
- 用户只要固定纸面文件时，仍先从同一 JSON 生成 HTML，再打印成 PDF；禁止维护内容不同的第二套报告。
- 简短问答不强制生成文件。只有用户要求完整报告、长期保存、PDF、HTML 或可视化时使用本规范。
- 输出文件名默认使用 `分析日期_四柱.html` 或 `分析日期_四柱.pdf`，不额外添加“结构详析”“性格分析”等显而易见的后缀，除非用户指定。

## 二、内容深度

完整报告按以下顺序组织，缺失数据时明确写原因，不用空话填页：

1. 阅读说明：输入、历法口径、候选盘、分析范围与版本。
2. 结论先行：当前最优结构、置信度、关键机制、最强异议。
3. 命盘事实：四柱、藏干、十神、月令、根气、透藏、合冲刑害与季候。
4. 五轨裁决：格局、旺衰、调候、从化、病药；只呈现参与最终裁决的内容。
5. 综合优先因素：功能、适用条件、失效条件、副作用，禁止只列“喜水木”。
6. 人格与行为机制：外在表现、内在驱动、压力反应、优势、风险、反证。
7. 学业、能力与职业领域：领域匹配机制、现实门槛、工作方式、风险与替代路径。
8. 财富、关系、居住／迁移、健康传统象义等用户需要的主题；高风险主题遵守安全边界。
9. 大运总览：顺逆、起运算法、交运误差、每步大运的主机制与主题变化。
10. 流年细读：只详细展开用户关心窗口或真正改变结构条件的年份，不为凑篇幅逐年重复套话。
11. 可执行建议：分别列环境选择、能力建设、关系做法和风险管理；不得把物品补五行写成必然改变命运。
12. 可验证问题、失败条件、来源与方法版本。

详细不等于重复。每个结论至少包含一条盘面依据和一个限制条件；同一机制不要在多个章节换词复述。

## 三、职业与领域

职业部分使用“领域匹配”，不用“命中注定职业”。每个候选领域固定写：

- `fit`：报告内相对匹配度 `0-100`，只用于同一报告内排序，不宣称客观测量；
- `mechanism`：它承接命局中的什么能力、结构或工作偏好；
- `suitable_roles`：适合的任务形态，而不只是行业名；
- `prerequisites`：教育、技能、资源、性格训练或地域等现实门槛；
- `risks`：该领域会放大什么结构代价；
- `evidence_needed`：什么现实表现会提高或降低匹配判断；
- `confidence`：命理体系内置信度，与现实职业成功概率分开。

优先分析任务形态：研究、分析、表达、组织、谈判、审美、照护、技术实现、风险控制、创业等。行业只是这些任务形态的组合。若教育、经历和兴趣未知，结论分辨率停在领域层，不锁定岗位。

## 四、大运与流年

每步大运固定写六项：

1. 干支分别进入原局后触发的关系；
2. 对格局、承载、调候、病药四层的影响；
3. 最可能突出的宽主题；
4. 现实条件成立时的机会；
5. 过载、反噬或结构代价；
6. 置信度、失败条件与交运边界误差。

流年不得只写“吉／凶”。每个重点年份写成：

`年份干支 → 引动原局／大运的关系 → 条件性主题 → 可利用方式 → 风险 → 什么算判断失败`。

若大运起运口径未核，不生成伪精确年龄。可以先呈现干支顺序或候选交运区间，并明确哪些年份会因交运误差归属不同。流月只在用户有具体时间窗口时加入。

## 五、报告数据契约

调用 `scripts/render_bazi_report.py`。输入为 UTF-8 JSON，顶层字段：

- `meta`：`title`、`subtitle`、`analysis_date`、`chart_label`、`calendar_note`、`model_version`、`privacy_note`，可选`status_tags[]`；缺柱时四柱连续标题直接写“未知”，解释放入副标题、状态标签和历法口径，不在同一行重复“时柱未知”。
- `summary`：`verdict`、`confidence`、`confidence_note`、`key_mechanism`、`strongest_objection`；
- `chart`：`columns` 与 `rows[{label, values}]`；
- `structure_facts[]`：`title`、`text`、`status`；
- `models[]`：`name`、`question`、`conclusion`、`confidence`、`evidence[]`、`conditions[]`、`failure_conditions[]`；
- `priority_factors[]`：`label`、`priority`、`function`、`conditions`、`failure_conditions`、`side_effects`；
- `personality[]` 与 `themes[]`：`title/name`、`summary`、`details[]`、可选 `confidence`；
- `domains[]`：使用上一节的职业字段；
- `luck_cycles[]`：`name`、`years`、`ganzhi`、`confidence`、`summary`、`mechanisms[]`、`opportunities[]`、`risks[]`、`failure_conditions[]`、`years_detail[]`；
- `actions[]`：`title`、`why`、`steps[]`、`tradeoff`；
- `validation_questions[]`、`sources[]`。

渲染器允许省略非核心数组，但 `meta`、`summary.verdict`、`summary.confidence` 必须存在。文本可以包含普通换行；渲染器负责转义，不允许输入任意 HTML。

## 六、生成与验收

```bash
python3 scripts/render_bazi_report.py report.json --output output/四柱报告.html
python3 scripts/test_render_bazi_report.py
```

验收：

- 单文件、离线打开，不依赖 CDN、网络字体或外部脚本；
- 白底、黑灰为主，屏幕与 A4 打印风格一致；
- 可点击展开全部大运与逐年细读，可一键展开／收起、搜索、返回顶部和打印；
- 导航、表格、长文本和折叠内容在手机与桌面均可读；
- 打印时自动展开折叠内容，隐藏按钮和侧栏，不截断关键表格；
- 图表只表达报告内相对比较，必须显示“非客观测量”的说明；
- 不出现空章节、占位符、调试字段或未转义内容；
- 生成后在浏览器检查交互，再看打印预览。若另存 PDF，按 PDF 技能逐页渲染检查。
