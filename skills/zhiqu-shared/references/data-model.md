# 数据模型：高考与考研共用

高考、考研的数据本质相同：某校某专业某年，招多少人、线是多少、录取分数怎么分布、数从哪来、核对过没有。两边按同一套规则存放，报告程序只读“可直接使用”的视图。就业数据（岗位、工资价位等）按相同的来源与核对规则存入独立就业领域库。

## 一、两层存放

| 层 | 放什么 | 格式 | 是否进 Git |
|---|---|---|---|
| 公开层 | 自己从官网取的官方数据 | 整洁 CSV（一行一条记录），每个目录配 `sources.csv` | 进 |
| 本机库 | 公开层的全部数据 + 购买或第三方整理的数据 + 核对结果 | 两个 SQLite：`skills/zhiqu-shared/data/education/education.sqlite`（教育：高考与考研）、`skills/zhiqu-shared/data/employment/employment.sqlite`（就业） | 不进（`.git/info/exclude`） |

每个领域目录各有可重跑的 `ingest.py`、`datapackage.json`、CHANGELOG.md 与版本记录，从公开层、结构化数据和核对凭据生成，不手改数据库；每次入库前留快照到 `snapshots/`。原件仅在会话缓存临时取得，按第七节完成摘录、定位与指纹保全后删除，不作常驻输入依赖。公开示例报告只能用公开层数据，真实客户报告可以用本机库。

## 二、共同约定

- **列名**用英文 snake_case，值可以是中文；年份为整数，日期 ISO（YYYY-MM-DD），分数为数值，原文写法另存 `*_raw`。
- **学校身份**：以教育部《全国普通高等学校名单》的 10 位标识码为主键 `institution_id`（见 `skills/zhiqu/data/schools.csv` 的 `id`）；各种校名写法、曾用名、各省招生代码、研招单位代码都进别名表，不在业务表里用校名做连接。对不上的列入问题表，不猜。
- **专业身份**：本科用《普通高等学校本科专业目录》代码，研究生用《研究生教育学科专业目录》代码（门类 2 位、一级学科／专业学位类别 4 位、专业 6 位），各自一张字典表。
- **来源**：每条数据都带 `source_id` 和原始 `src_row`；PDF/图片另带 `src_page`、`src_table`。字段与原件保留规则见下文「来源与原件」，不以整理CSV的行号冒称原件页行。
- **核对**：与官方原文抽查的结果统一记在 `check_sample`，结论只用四种：一致、不一致、口径不同、未取到。
- **可直接使用的视图** `v_usable_*`：官方数据优先；第三方与官方不一致时用官方值并注明；没核对过的标“第三方整理，未核”。报告和模型只读这些视图。

## 三、共用的表

| 表 | 主键／要点 | 说明 |
|---|---|---|
| `meta`、`ingest` | 入库批次、脚本 sha256、时间 | 可追溯每批数据由哪个版本的脚本生成 |
| `source` | `source_id` | 见上 |
| `institution`、`institution_alias` | `institution_id`；别名含 `kind`（校名／曾用名／省招生代码／研招单位代码）、适用省份与年份 | 教育库只存一张权威学校身份表；就业库引用时在应用层核对编号，不另造身份副本 |
| `discipline` | `level`（本科／研究生）＋`code` | 专业字典 |
| `check_sample` | 表名、行键、字段、库内值、官方值、官方 `source_id`、结论、核对日期 | 抽查记录 |
| `ingest_issue` | 文件、行、问题类型、列、原值 | 解析不了或对不上的行 |

## 四、各领域的业务表

两边的“一年一行”和“分数分布”同形，只多出各自特有的列。

| 概念 | 高考 | 考研 |
|---|---|---|
| 招生单位 | `plan_entry`：省份、年份、科类、批次、学校、专业组、专业、计划数、学费、选科 | `program_year`：学校、学院、专业代码、年份、学位类型、全日制与否、招生人数、推免人数、考试科目 |
| 线 | `result`：最低分、最低位次、平均、最高、录取数 | `program_year.line_total` 及单科线；`national_line` |
| 分布 | 一分一段表 `yfyd`（分数→累计人数） | `score_dist`：名单类型（复试／拟录取）、一志愿或调剂、专项排除数、n、min、q1、median、q3、max |
| 官方表 | `official_cutoff`、`official_yfyd` | `official_line`、`official_dist` |

分位数统一用含端点线性插值；排除了哪些专项、是否含调剂，必须在行里写明。

购买汇编全量导入时，先按原件 SHA256 去重，并保存文件清单、实际表头与列映射。来源绑定须同时核对完整相对路径和原件指纹，不用同名文件覆盖来源字典。同口径（省份、年份、科类、批次、院校、专业或专业组、计划类型、适用范围）同字段同值只存一次，多个来源通过关联表登记；不得跨方向、专项、校区或旧文理／新物理历史合并。数字事实、同一来源行内数字的组合、来源位置分别存放，避免把不同原行的数字拼成一行。`gk_purchased_record`／`gk_v_purchased` 保留兼容查询，`purchased_record_source` 保留所有来源定位。文件字节不同、但已入库匿名片段逐格同类型同值时，可由 `employment_source_equivalence`／`employment_industry_version` 关联到一份事实；关系须限定已核片段，内容指纹不能冒充原件指纹或完整文件等价证明。

限时补列使用 `core_delta_*` 保存具名字段、完整适用范围和逐格来源，`v_core_delta_number`／`v_core_delta_attribute` 供统一查询。已在上下文字典中保存的值通过 `core_delta_context_field_source` 只关联出处，不另存一份属性值；原表方向、专业完整名、专业组、选科和计划性质均参与范围区分。无法解释的列登记表头；范围未闭合时按原件、表、物理行隔离，不凭字段名相近跨版本合并。后补的范围与生源省份按同来源、同表、同物理行关联，完整业务范围以最终视图为准，不直接对字段值字典求和。资料包的省份／年份仅为提示，不能代替原表依据；缺证定位键分别用 `core_delta_province_unconfirmed`／`core_delta_year_unconfirmed` 保留，最终查询屏蔽提示值并显示未确认状态，别名适用区间也不能据此满足。补入状态、逐值官方核对和文件完整性分开记录；省份／类别已有抽查不代表该文件每格或新增字段已获官方核准。

不长期保存整份匿名原始行 JSON、压缩块或全量单元格副本。审计仅保留每源的原件指纹、表头／映射、行号范围、明确算法的结构摘要和最多 3 行抽样；连续位置可用精确等差区间无损表示，查询仍须给出具体页／表／行。未留全文的行应明确说明，不能把抽样当成该行原文。反复出现的文字、质量状态和原句可字典化；无消费者的中间表、索引及已替代的物理副本应移除，随后 `VACUUM`。发布验收后删除候选库、写入进度日志及 `full_ingest/inputs` 回放数据，每个领域仅留一份回滚库，保留入库脚本与必要审计结果。移除旁注形成真实范围后，若同范围同年同字段有不同第三方值，保留各值及各来源，单列冲突标记，不自动选值；该字段查询提示待核，相关文件默认暂不得删除；用户明确授权清空指定目录时，先逐文件登记指纹、入库范围及未补原因，再按授权删除，不能据此把未补入或未核数据标成已完成。原表旁注只选取有用途的学校背景属性并标第三方未核；不能继续把所有未知列塞进 `scope_raw`。来源列出的范围、条件、备注保留；无法解释的列只登记表头和问题，不整列复制。

院校概况、全国专业介绍和就业去向不得借资料包目录所在省或该省招生代码推定学校身份。专业介绍里有用且尚未结构化的选科建议、专业解释、学习内容和就业方向须先迁为具名属性，再移除全行副本。未唯一闭合批次或方向的官方重叠只记候选，不自动纠错。

就业去向的 `graduate_destination` 分开保存地区、单位性质、单位名称、明确人数、百分比、排名及原句；届别未写则记「未注明」，不得把另一届就业报告的比例套用为该行官方值。专业就业行业表保留原列占比、单位与届别；未明确百分号或比例基准的数字不得自动换算成百分比，逐值状态须说明单位未闭合。专业概况 `major_profile` 与历史群体比例 `major_reference_stat` 分开：本科与专科不混用目录身份，修业年限须有逐专业依据；往年就业率区间仅作第三方参考，不能单独支撑报告结论。公式无缓存、缺失工作表成员等结构问题要单列，不把未读到的数值标成来源未提供。文件完整入库、核对已执行并登记「已入库」后才可按删除清单删原件；部分解析、未完成隐私处理、非数据及不能入库的原件继续保留并列原因。

## 五、查询

统一入口 `skills/zhiqu-shared/scripts/zhiqu_db.py` 接受 school／program／jobs 子命令，输入学校（任何写法）、专业或地区，列出历年招生、线和分布，并标明每个数的等级、逐值质量与来源。报告程序只读可用视图。教育库用 `gk_`、`ky_` 前缀区分原有高考与考研业务表/视图，保留必要兼容入口；学校、别名、学校事件、专业字典、来源等共同实体不按前缀重复建权威表。就业到教育库的学校或专业引用由应用层检查，不能宣称 SQLite 存在跨数据库外键。

## 六、现状与迁移

- 教育与就业按上述两个领域目录组织；旧 `purchased.sqlite`、`kaoyan.sqlite` 是迁移来源与兼容入口，不再各自维护学校权威表。原高考业务表/视图迁为 `gk_*`，原考研业务表/视图迁为 `ky_*`；业务值、出处定位与历史差异凭据保留，公共实体冲突须显式记录并建立旧新来源 ID 对应。
- 公开层各省目录仍配 `sources.csv`，每行带 `source_id`（`validate_data.py` 检查）；官方表与学校身份、核对记录保持实际关联。重建由领域目录 `ingest.py` 实施先快照、候选文件、自检、原子替换，不在另有读者访问的正式库上分步写入。
- 学校身份按校名、曾用名对上教育部名单；对不上的（军队、港澳院校，学校下属医学院，名单外的旧校名、简称和识别错字）记入 `ingest_issue`，不按招生代码猜。补全曾用名在 [school-name-changes.csv](../../zhiqu/data/school-name-changes.csv)。

## 七、来源与原件

`source` 与公开层 `sources.csv` 使用同一顺序的17列：`source_id`、`grade`、`publisher`、`title`、`landing_url`（公告页）、`file_url`（原件附件直链，无则空）、`published`、`retrieved`、`method`、`archive_sha256`、`archive_path`、`archive_status`、`wayback_url`（可空）、`note`、`citation`、`license`、`producer_revision`。等级仍只用官方／第三方整理，发布单位与等级分开。旧url按实际类型迁移，旧文件名、SHA及其他元数据在本机 `source_legacy` 原样保留；此表是迁移凭据，不是原件。官方来源至少有公告页或附件网址；栏目、首页只作为入口，不证明数字已取得。

原件按「临时取得 → 入库摘录、页/表/行和完整字节指纹 → 逐值核对并保留结论 → 删除原件」处理。公开官方与购买原件均只放会话 `.cache/` 临时目录，不把原件、整页全文或二进制副本留进 Git、常驻原件库、ZIP 或其他留底副本。实际核过哪些值写入 `check_sample`，摘录必须是支持对应值的逐字原句/单元格，不用整理CSV拼接冒充；图片按物理页/图表和原单元格摘录，OCR仅是候选，须实际读图才能判通过。删除前记原路径、大小、真实 SHA256、来源链接及核对记录定位的 manifest；旧索引/成员表只可导出安全元数据，不复制原件内容。含个人信息的名单不输出身份字段、全文或名单行，只保留获准的聚合统计。

`archive_status` 使用「已核后删除（有指纹）」「已删除（有指纹，核对见记录）」「未取到」。前者须有明确逐值核对证据，不能因下载成功或一次抽查声称全源每个数已核；未逐值核准或只有部分抽核的使用后者，具体范围看核对记录。两种删除状态必须有64位小写十六进制 `archive_sha256`，且 `archive_path` 为空，不要求已删除文件存在。指纹只对实际取得的原件完整字节计算，不能用整理表、摘要、收据或网页标题冒充；历史真实指纹可在「未取到」保留，但路径仍为空，不能说已存。旧「已存原件」「原链接失效·存档副本」只为兼容历史数据接受，仍必须有可读文件且 SHA 一致；本轮公开来源清理后不再声明这两种已存状态。

`skills/zhiqu-shared/originals/` 已按授权删除，不再作为发布资源；`validate_data.py` 在其不存在时继续校验全部公开来源基本元数据，不要求空的原件索引。兼容旧目录存在的输入时仍验证索引、实际文件、大小、官方来源和成员关系，不能把删除政策用来跳过虚假的已存声明。DNS、限额、302预算不足与验证码不等于原链接失效；其他官方入口或实际取得的 Wayback 存档需记旧网址、发现入口、存档网址及适用年份，`wayback_url` 不猜填。

业务 `src_row` 原样保留，`src_page` 是原件物理页（从1起），`src_table` 为工作表名/表名/图表标识，`locator_method` 包括「读图」；无法定位页表就留空并用 `locator_status` 记缺口。整理CSV行只辅助检索，不能伪造为原件行。多原件汇编或分位数来源应注明原文件成员、工作表及统计范围；原件已删的数据显示删除状态、真实指纹、摘录和核对定位；未保留摘录或逐值未核的缺口须明示。query每个数字分别输出值、等级、发布单位、公告页、附件直链、指纹、原件删除/可用状态、摘录、页／表／行；官方替换只能追溯该字段实际匹配的官方行，非唯一时列候选，不把其他字段一并升级。派生值必须同时输出公式和各输入的来源链，例如位次需要投档分数与同年同科一分一段累计两项，不能只指向不含位次的投档原件；加分口径缺失或输入不符时标记未闭合，保留业务原值。

抽查在check_sample逐项记录实际库值、原文值、source_id、页表行及一致／不一致／口径不同／未取到，不修改业务数字。下载成功不等于数字一致，扫描件需实际读图或核实OCR；没有可靠原文时不能仅因出现相同数字就判一致。check_links.py按需经本机爬虫限额体检，各URL结果写link_check：source_id、checked、http_status、final_url、body_matches_archive，另记具体URL、状态与原因；无两端指纹时一致性为空，不用HTTP200替代正文核验，不自动定时运行。

每次入库先快照，写独立候选库，核对全部原业务字段/行数与原库一致、外键与完整性检查通过后fsync并原子替换。两库的datapackage.json采用Frictionless Data Package格式，记录schema/列说明/单位/实际主外键/来源列表/数据库SHA及版本；已知业务连接但未定义SQL外键的另作说明，不伪造约束。README数据字典从该文件生成，CHANGELOG按实际入库SHA记录批次，同库指纹重跑不重复写日志。公开CSV校验检查17列与状态对应的指纹/路径约束；仅在兼容旧原件目录存在时检查索引，默认离线运行。


本节的扩展约定（两库及公开来源目录共同遵守）：

- **学校存续**：institution增加status（在办／更名／合并入他校／撤销／转设）、successor_id、parent_id、established、closed、status_source_id；只凭教育部批复或学校官网沿革原文填写；若仅取得学校沿革关于教育部批准的原句，来源须写学校官网，并说明未取得批复正文，不冒称教育部原件。无原文留NULL。parent只表关系，不合并数据。单一学校码发生更名时successor可以是本码，不新造学校身份；institution_event另记旧名、新名、精确生效日期、继任码、原句和source_id。原学校标识码不同的合并或转设保留两个身份及生效事件，旧年份不回挂新校；按年份查alias并展示事件链，不自动重定向业务数据。只有年份的查询须注明年内时点未判定。
- **逐值质量**：业务表value_status是JSON映射，每个业务数值字段（含year/plan_year；ID及原件页行等定位键除外）各有status及必要的method/reason，不能只有行级标签。枚举：官方原值、人工更正、推算、第三方整理未核、第三方已核一致、未公布、人数太少未公布、来源未提供、原件缺失。人工更正的原始值、可用视图采用值和correction分开；推算写方法与输入链，核对只升级实际核过的字段。NULL不自动视作未公布或保密抑制，须原文明确；「来源未提供」只用于确实取得的来源未列该字段/未给该值，并说明依据，不能把取文失败叫来源未提供；缺失原因未核时用原件缺失并说明尚缺该空值的原文依据。等级、原件可用性、逐值质量是独立维度，query输出完整标记。
- **多成员原件**：图片承载数字时，HTML只是公告页，不算数字原件已齐。临时取得每张数据图，`source_asset` 保留 source_id、sha256、原网址、role、retrieved、摘录和图表定位；删除后 path 清空，来源 note 列出成员指纹及期望/已取张数。部分成员未取到时整体不声称已齐或已核；取得的成员可以单独保全指纹。导航图或验证码页不是数据图，不能充数。
- **可比性**：comparability逐条记录domain、scope、field、effective_year、change、impact、source_id及原句，只录实际取得的官方原文。改革前后科类、批次、专业组、专项计划口径和考试科目变化分别确认，不从一省推广全国，不将333可选统考写成强制统考。多年份查询跨过生效年份且省份/学校匹配时显示提示；表中没有记录不代表口径稳定。
- **引用与修订**：citation完整列发布机构、标题、年份、网址、取得日期；引用年份先取 published 的发布年份，其次取 title 中明确的年份，两者都没有则写「未注明」，不能拿 retrieved 取文年份代替发布年份；无公开许可填license=未注明，不擅自授予开放许可。producer_revision只记实际更正公告及日期，没有则空。dataset_version保存明确发布事件，不因脚本重跑自动升版：改字段/类型/约束升MAJOR，补数据或资源升MINOR，纠错或描述性元数据修订升PATCH。correction记录table_name、row_key、field、before_value、after_value、reason、affected_rows、source_id、date；迁移旧核对日志须注明历史纠错，并非本轮修改数字。CHANGELOG由持久版本、correction与入库批次自动生成；README字典仅从datapackage生成。Frictionless必须以实际SQL表资源验证，不能仅以二进制文件资源得到VALID就宣称逐表通过。
