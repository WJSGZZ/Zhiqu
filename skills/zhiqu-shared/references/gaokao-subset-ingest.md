# 高考子集入库与缺口查询细则

一原物理行对应一条业务观察的图片，也可按明确子集入库：主审看图抄写与独立Vision只对已批准行逐格一致，抽核仍为10%且至少5行；不一致的整行不入。原行/原格位置按原图实际横线与列界确定，不能用平均行高累推；起点、中段和末行须能对应真实像素边界。修正纯几何定位时保留原冻结稿、修正依据和原值指纹，不能随定位修改抄写值。`review.excluded_rows`逐行记原件SHA、正整数页/表/行定位及原因，不得与已入行或其他分区重复；`original_data_rows`须等于已入行加排除行，`extracted_rows`等于已入行，同SHA的`original_source_rows`与所有分区原行数合计闭合。不得将“已一致行数”冒充原表总行数，也不得丢失未读页的缺口；此来源范围保持partial。完整排除证明在批准清单只存一份，逐行审计只绑定排除数与证明指纹，不重复整份清单。

子集的缺口还须在本机库 `meta` 中以 `gk_source_coverage:<source_id>:<table>:<声明指纹>` 保存紧凑完整性声明：原表行数、已入行数、缺失原件页/表/行及原因、未读范围；只追加新声明，查询使用最新追加项，不覆盖旧凭据。默认学校查询须提示原表不完整并列缺行，`--full`显示全部原因；一分一段查询由 `zhiqu_db.py yfyd` 与 `rank.py Table` 共用门禁。原表没有的分数、跨缺行的位次区间、标为插值的原非官方点及表外范围均返回“该段缺数据”，不得取下一档、跨缺口插值或累加缺行之后的人数。只有明确公布的本段人数能单独证明该分数的同分区间；查询须同时核对 `count_kind` 和逐值状态，不能因为列名为 `segment_n` 就把累计、口径未明或推算的人数当本段原值；不能把跨缺行累计差当本段人数。补齐时重交包含既有行和补入行的完整批准清单，原业务行、原摘录和原定位必须相同，旧审计原样保留，仅新增事实与完整性声明。所有报告、回测、估分和等位分换算共用此门禁；不因报告需要而补数。
