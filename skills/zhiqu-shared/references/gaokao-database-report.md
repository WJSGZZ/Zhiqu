# 高考数据库报告的缺口与交付

新报告运行前先看各年导出行数和拒绝原因，空表不当作最近历史年；河北跨年按校名对应（`pool.py --school name`）。批次或专业范围不明不手填猜测；仅旧年第三方可用时如实按D级讨论，并把当年资格、费用、代码列待核。数据库填报单逐行注明历史代码年份，不能直接用于未来年度填报。未取得院校调研时，模拟稿可显式写 `research_status: pending` 和 `research_gap_reason`，逐项列“未取到＋原因”；这不是完成调研，正式交付仍被拦。正文数据结构以[报告指南](../../zhiqu/references/report-guide.md)为准。

高考数据库新报告在生成后运行 `claim_check.py build`、`bind`，再由独立会话逐句填写；`case_check --stage 8 --delivery` 同时检查独立批准与清单。写作会话只准备待复核材料，不填独立结论。细则见[逐句回查](claim-check.md)。

`source_details` 的摘录只能来自实际留存的原文或数格；库内数格要明确原件已删和原始等级，不能用报告自己的话冒充官方摘录。尚未取得的原文保持未取到。

先完成阶段0—6的登记、画像、方向、规则缺口、筛选计数、打分依据和实际计算，再生成报告；PDF附件复算、等级逐值检查、版面检查和逐页速览完成后，留给独立会话复核。阶段7可通过不代表阶段8获准交付。
