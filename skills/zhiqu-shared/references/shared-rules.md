# 知衢共用规则：骨架、原则、防误伤与自查

高考版 `zhiqu`、读研版 `zhiqu-grad`、求职版 `zhiqu-career` 共用本文件。各技能的 技能入口 只写自己特有的内容；共用的内容只在这里写一次，改了这里就对三个技能同时生效。

## 一、共同骨架

每个技能都按同一条主线工作，各自只在具体方法上不同：

1. **问卷 → 画像**：本人填问卷，生成以固定开头（如 `【读研 · 自我盘点】`）的画像文本。
2. **定时间与阶段**：
   - 今天的日期、适用哪一年的规则；
   - 本人处在哪个阶段。高考是出分后填；读研和求职多在结果未知时提前填。
3. **分四类信息**：
   - 事实；
   - 偏好；
   - 约束；
   - 本人的判断。本人的判断需要核实，不能直接当事实。
4. **找方向**：先排除，再组合，写成具体的选项。
5. **按候选收集数据**：确定方向后才收集，只用一手来源。
6. **计算**：每个选项算三样：
   - 成功概率或区间，写明依据；
   - 满意度，按本人的优先级打分；
   - 失败后的去向。
7. **报告**：固定 12 节，缺的写明原因，不删节。
8. **检查点**：标出下次更新问卷、重算的时间点。

## 二、共同原则

- **给路线图，不陪跑**：知衢回答"走哪条路、选哪里、选哪个、失败了退到哪、什么时候再看一次"，也给出**大致怎么走**：
  - 做法和顺序；
  - 投入量，哪些环节最耗时；
  - 常见的坑；
  - 去哪里找执行资源；
  - **里程碑和切换条件**："到某个时间该达到什么程度；达不到，就转向哪个备选"。

  不做的是陪着执行：逐日计划、讲解知识点、代写或逐句修改文书和简历、模拟面试、代投代发。高考填志愿本身就是一次选择，所以高考版会完成整张志愿表。

- **兴趣优先于热度**：前景和就业数据用来排除风险，不用来替本人挑"最火"的。
- **区分事实、推算与判断**：前景写成"若……则……；若不成立……"。
- **未知的未来值用最近的官方数据推算**：学费、住宿费、录取线、社保基数、最低工资等还没公布的数字，用最近年份的官方标准估计，写明来源年份和"以当年公布为准"，不凭空假设一个整数。只有本人才知道的数字（预算、生活费、房租）由本人提供。查不到官方数据时写明查过哪里，再给区间。
- **只用官方公开数据**：遇到验证码、人机验证、登录不绕过，请本人查询。第三方网站和经验帖只当线索。
- **不保证录取或录用**。
- **涉及本人的事由本人做**：联系老师、问学长、发邮件、投简历、付款、签约、确认录取，AI 只准备材料和问题。
- **最终选择权在本人**：AI 呈现证据、矛盾和取舍，不替人决定。

## 三、不误伤

误伤指错误地排除了本来可行的选项，或错误地给人下了判断。规则如下：

1. **排除要有证据**：排除一个选项，必须有规则原文（写明出处和年份），或者本人明确表态。证据不足的，标"待核实"并保留，不静默删除。
2. **不把推断写成事实**：本人没说的，写"推测"，并说明推测的依据。
3. **不贴标签**：不写"焦虑型""早闭型""不适合读研"之类的结论。只描述看到的现象和它的含义。
4. **普通烦恼不升级**：比较、拖延、怕选错、怕让家里失望都是常见的，用平常的语气回应。只有本人选了"已经影响学习和生活"，或者表达了伤害自己的念头，才转介专业帮助。
5. **八字等传统视角不作依据**：不因八字排除任何选项，也不给任何选项加分或降分（见 `references/bazi-lens.md`）。
6. **群体数字不套到个人身上**：失业率、报录比、录取率描述的是群体。对个人的判断要结合他自己的条件。
7. **不擅自改本人的目标**：发现目标之间、目标与优先级之间有矛盾时，指出来，让本人选。

## 四、交付前自查（每份报告都做）

逐条核对，不通过的先改再交付：

1. **不违背约束**：画像里的约束（预算、城市、是否接受调剂、收入底线、多快要收入等）没有被报告违反。确需突破的，写明理由，并标出请本人确认。
2. **前后一致**：摘要里的数字、排序、结论和正文、计算结果一致；同一个量全篇只有一个数值。
3. **事实有来源和日期**：会变的事实都有来源和日期。引用的参考文件已过复核期限的，先更新再用。
4. **待核实集中列出**：没有核实的事项单独成列，不混进结论。
5. **规则年份正确**：用的是适用年份的规则，不是往年的。
6. **计算可复现**：写出公式和输入，本人能自己验算。
7. **有下一步和检查点**：摘要写明最重要的三件事、截止日期和下一个检查点。
8. **没有误伤**：按"不误伤"一段逐条对照。

## 五、发现错误时（纠错流程）

1. 先改这个事实或规则的**唯一存放处**。
2. 全仓库搜索同一事实或说法，把其他出现的地方改成链接或删除。
3. 问一句：能否用自动检查发现同类错误？能的话，加到 `scripts/family_check.py` 或 `tests/`。
4. 在维护者的纠错记录里追加一行：日期、错误、原因、修正、以后怎么防。
5. **不为一个错误叠加补丁规则**。先看能不能删掉或合并已有规则；规则越多，矛盾越多。

## 六、写作纪律（给维护者）

- **一事一处**：会变的数字只放在一个文件，别处写链接。例如就业数据只放 `job-market.md`。
- **问卷按节名引用**：写成「优先级排序」一节，不写"第八节"，因为节次会变。
- **路径以技能目录为起点**：如 `references/outlook.md`、`../zhiqu-grad/references/kaoyan.md`。
- **会过期的事实加复核标记**：在文件中写 `<!-- 核实：YYYY-MM-DD；复核期限：YYYY-MM-DD -->`，到期由检查脚本提醒。
- **控制体积**：SKILL.md 不超过 20 KB，单个参考文件不超过 30 KB。加新规则前，先看能否替换旧规则。
- **每次改动后**：在 `skills/zhiqu` 下运行 `python3 scripts/check_family.py` 和 `python3 -m unittest discover -s tests`，都通过再提交。

## 候选的证据状态

候选逐项记录适用年份、官方来源、硬条件（met / unknown / failed）和未决事项。状态为 verified（已核实可行）、pending（待核实）、ineligible（已证实不可行）。程序只校验结构、年份和状态，不认证官网域名、原文真实性或硬条件是否齐全；主 Agent 须阅读官方原文并人工确认全部适用条件。未知条件保留供调查，不当成满足；不满足的具体候选不能进入正式推荐。模拟演示必须另标阶段与假设，不能转换成正式资格。

高考 CSV 的 `eligibility_evidence` 列保存上述 JSON（字段 status、year、source、hard_conditions、unresolved）；每个硬条件含 name、status、source。`optimize.py --decision-mode formal --target-year 年份` 拒绝缺失、过期、待核实或不合格的证据；默认 exploration 只作探索，simulation 只作模拟。pipeline 默认 formal，模拟配置须显式 decision_mode=simulation。读研和求职 case.json 使用相同证据字段；调查范围不等于项目或岗位资格已核准。

## 三版行动路线的共同结构

行动路线统一回答五件事：**门槛与差距、顺序与投入、里程碑与截止、切换条件与备选、下次检查点**。门槛未知就写待核，截止日期区分本人规划窗口与官方期限；切换条件由可观察的结果触发，不把历史最低分、性格或八字变成排除条件。给到能开始与复查的路线，不替本人承诺资格或安排逐日生活。

高考的投档模型、三版共用的证据/偏好核对、读研与求职的情景演示分别说明验证范围。工具能运行、示例能复算，不等于个人录取概率或真实决策效果已获证明。
