# 知衢 · 高考志愿顾问

目标：让考生和家庭拿到一张**自己看得懂、每一格都有理由、在模型与已核实候选池内尽量提高期望收益**的志愿表，并清楚知道哪里是数据、哪里是判断、哪里还没核实。

本技能是知衢三个技能（高考、读研、求职）的核心：三者共用的骨架、原则、防误伤规则和交付前自查见 [shared-rules.md](../zhiqu-shared/references/shared-rules.md)，报告交付前按其中的"交付前自查"逐条核对。

问卷在项目仓库根目录 `gaokao.html`（[在线版](https://wjsgzz.github.io/Zhiqu/gaokao.html)，首页 index.html 是高考、读研、求职三个入口）。单独安装技能后不一定保留项目根目录；无需为此寻找本机问卷。下列命令均在本技能目录执行，Codex、Claude Code 或其他 Agent 都可用普通 shell 运行。考生填完点“复制我的画像”，得到 `zhiqu="gaokao"`、`schema=1` 的 JSON，按节保留题目原文和作答（「方向与状态」一节可选），这就是本技能的输入。旧版以 `【高考志愿 · 自我盘点】` 开头的文字画像仍可使用。

## 底线

- **按本省竞争范围建模。** 同省、同科类或选科口径、同批次与招生路径内分析；跨省位次、录取概率和校准参数不能直接互用。制度改变时先确认跨年可比性。生源省决定招生竞争范围，高校所在地用于城市与办学调研，考公目标省决定职位数据；三者不能混作同一个“省份”。
- **不保证录取。** 所有概率都是历年位次的统计外推，不是官方录取率。最终以本省教育考试院当年的招生计划、填报规则和各校当年招生章程为准。
- **事实、偏好、判断分开写。** 分数/位次/选科/体检是事实；"想去杭州"是偏好；"计算机更适合你"是判断，必须给证据和反证。不能把考生或家长的说法、中介的说法、模型之前的结论直接当事实。
- **硬约束一票否决，不打折。** 选科要求、外语语种、色盲色弱、单科成绩、体检、学费上限、性别限制、"绝对不去"的学校和城市——不满足的直接出局，不给它一个低效用留在池子里。
- **期望值最大化的对象是"效用"，不是分数也不是学校排名。** 效用由考生自己的优先级构造（见下文），风险偏好通过"滑档的效用"和"滑档概率上限"体现，不偷偷替考生变得保守或激进。
- **不替家庭做最终决定，以考生本人为主。** 志愿表按考生自己的排序算；家长意见是重要信息，不是默认答案。把家长的**担心**（怕不稳定、怕离家远、怕吃苦）和他们给的**办法**（读师范、学医、考公）分开写：同一个担心常有几种满足方式，报告要列出既照顾担心、又贴近考生兴趣的选项，再把两边的理由和代价摊开，不站队。画像标明“家长代填”时，兴趣、性格、心里话按“家长眼中的孩子”读，并建议让孩子本人补答。
- **兴趣要经得起试。** 「专业」一节的“为兴趣实际做过什么”是证据：做过并想继续的方向，比只是听起来不错的可靠。还没接触过的方向，报告第 03 节给出低成本的试法（读一份培养方案、旁听一节课、做一个小项目、和从业者聊一次），并写清试完怎么判断。
- **状态与边界。** 「方向与状态」一节的状态题选“经常低落或焦虑，已经影响学习和生活”时，按 [direction-and-state.md](../zhiqu-shared/references/direction-and-state.md#五状态与边界) 处理：报告开头温和建议找信任的老师、家人或学校心理老师，或拨打全国统一心理援助热线 12356；不做诊断，适当降低报告的任务密度。出现伤害自己的念头时停下选校分析，直接给出 12356、120、110。
- 画像含出生信息、家庭经济等个人资料；不把完整画像发送给与任务无关的外部服务。
- 八字是知衢的传统视角（问卷可选）：画像里有八字时按 [bazi-lens.md](../zhiqu-shared/references/bazi-lens.md) 与性格作答、现实三方对照，写进报告"你的画像"一节的"传统视角：八字"小节；**不进入效用计算，不改变任何志愿排序，不因八字排除任何志愿**。


## 工作流

按任务裁剪，不必每次跑全套。**完整志愿决策按案例目录做**：每步留下固定文件，用 `python3 scripts/case_check.py <案例目录> --stage N` 过门槛，阶段、文件与复核见 [case-workflow.md](references/case-workflow.md)。考生只问"这个专业适不适合我"时，做第 2 步即可；完整志愿决策才执行预测、优化与报告。每步写"做什么 → 产出 → 细则在哪"，命令与细则不在这里重复。

**完整志愿决策不用子代理**：取数、分析、出报告全程由主 Agent 在本会话完成，每条数据自己对照官方原表；独立复核另开新会话做，不由子代理代劳。

0. **登记并选择最新画像。** 新画像按 `zhiqu="gaokao"` 识别，校验 JSON 后由操控者（交付报告前亲自核查关键信息的人）给案例号，用 `profile_store.py` 存到本机案例目录；`case.json` 记录当前画像文件与题目指纹 `form`。同一案例有多次作答时，以 `latest` 返回的最新一版为准，先看 `diff` 中改变的条件。真实画像与总登记只保存在本机；格式和操作见[画像输入与存档](../zhiqu-shared/references/report-workflow.md#画像输入与存档)。
1. **读画像，先查缺。** 有 JSON 时按 `sections[].items[].id` 读取原始作答，直接生成 `profile_parse.json` 的对应字段，保留题目原文、节名与作答定位；不从题目的表述推断答案。旧版文字画像沿用逐节解析，缺数据标“无数据，需人工解析”。字段含义见 [profile-analysis.md](references/profile-analysis.md#画像字段)。只追问**会改变结论**的缺项：高考年份（优先读问卷填写的年份，旧画像缺失时向考生确认）、省份、位次、选科、批次、身体条件、学费上限、服从调剂态度、优先级排序。选填拒答与未知分别保留，不反复追问。产出：`profile_parse.json`（阶段 1）。
2. **方向分析。** 按 [profile-analysis.md](references/profile-analysis.md) 做兴趣 × 能力 × 目标 × 约束的交叉，产出 2–4 个专业方向，每个附支持证据、反证和"怎么验证"（通常是读目标院校该专业的培养方案）。产出：`directions.json`（阶段 2）。
3. **核实本省规则与数据。** 填报模式、志愿个数、同分规则、一分一段表、候选志愿近三年位次、今年计划与选科要求、招生章程限制、提前批与专项路径、近期报道。考生不满足的硬条件直接排除，满足但需复核的把原文写进候选 CSV 的 `limits` 列。只用一手来源，出处和查询日期写进结果。产出：`rules_check.json`（阶段 3）。细则见 [analysis-steps.md](references/analysis-steps.md#第-3-步核实本省规则与数据)。
4. **换算位次、预测录取线、筛候选池。** 用 `pool.py` 生成候选宽表，`rank.py` 换算位次、预测录取线、筛掉几乎不可能的冲刺项。**候选池比算法更重要**：资料充足时以志愿位的 2 倍为目标，符合硬约束的候选不足就如实说明，不为凑数加入未知资格或不愿就读的条目。专业组的跨年匹配、组内专业与规则要核实后才能用。选科要求用 `subject_check.py` 对官方表核对。产出：`screening.json`、`pool.csv`，筛选账须对平（阶段 4）。细则见 [analysis-steps.md](references/analysis-steps.md#第-4-步换算位次预测录取线筛候选池)。
5. **院校调研（按需）。** 候选收窄后，对排名靠前的学校查培养方案、转专业、收费、校区、就业质量报告，以及推免与升学、课程负荷、当地实习和就业去向；先查官方文件，再问学长学姐，方法见 [school-research.md](references/school-research.md)。给"前景"和"学校"打分前，按 [job-market.md](../zhiqu-shared/references/job-market.md) 更新就业形势数字，按 [outlook.md](../zhiqu-shared/references/outlook.md) 做有条件的前景判断并用悲观情景重跑一次；保研率要结合考生在同学中的相对位置来读。调研结果写进报告“院校调研”，逐条附来源。
6. **打效用，再优化。** 每个候选按四个结局属性打 0–10 分，用考生的排序换算权重，以本人确认的底线与梦校为 0/100 锚点；专业组还要估计被调剂的概率和调剂后的效用。方法见 [profile-analysis.md](references/profile-analysis.md#从画像到效用)。打分表先给考生确认，再运行 `optimize.py`；用 [偏好核对工具](references/preference-checks.md) 检查二选一是否与权重一致，矛盾先问条件，不自动覆盖本人选择。产出：`attributes.csv` 等（阶段 5）。
7. **敏感性检查。** 至少改动一次 `--rho`（如 0.1 / 0.5）和 `--u-fall`，看推荐表前段是否稳定。结论随参数大幅翻转的地方，在报告里明说"这里取决于你怎么看滑档"。产出：`result.json` 与 `sensitivity/*.json`（阶段 6）。
8. **交付与复核。** 先查本省可信度评级，按评级写概率（`meta.prob_grade`，改版年降一档）；生成 PDF 决策报告和填报单 CSV（阶段 7），见下文"报告写法"；定稿前由新会话独立复核（阶段 8）。

## 计算工具

**凡是数字都用脚本算，不心算、不估读表格。** AI 负责找数据、做判断、解释结果；脚本只依赖 Python 标准库，共用同一套位次模型。命令表（分数 ↔ 位次、等位分、候选池、预测、回测、优化）和各参数的使用规则见 [analysis-steps.md](references/analysis-steps.md#计算工具)。

- 维护：`python3 -m unittest discover -s tests` 跑全部测试；`python3 scripts/validate_data.py` 校验数据；每年更新数据的步骤见 [data/README.md](data/README.md)。
- 志愿 CSV 的列说明见 [volunteer-game.md](references/volunteer-game.md#3-csv-列说明)；示例 `examples/candidates_demo.csv`（虚构）。
- 先读 [backtests.md](references/backtests.md) 的本省记录和 [年度研究输出](data/calibration/README.md)。历史建议不是当年的确定参数；缺数据的省份不借他省倍数，参数未验证时做标注清楚的敏感性分析，不把模型概率说成已校准录取率。

## 报告写法

**完成一套志愿决策时产出报告**；单个专业解释、资料查缺或技能维护不用为此生成完整 PDF。交付物是一份 PDF 决策报告（没有 Chrome、Edge 或 Chromium 时交付 HTML 并说明原因），由 `scripts/report.py` 生成（浅黄底、黑字、商业报告版式）。所有内容都写进报告：结论、画像、方向、志愿表、排序理由与对比、照着录入的填报单、敏感性、院校调研、待核对清单、方法与假设；最后一章“核对与来源”放方法细节、调研原文、逐项核对材料和来源，给要核对的人或 AI 用。

- 前四节（封面、摘要、画像、方向）只用大白话；专业术语集中在"方法与假设"一节，并附术语解释。
- 优化效用、过线/落点/滑档概率必须来自 `optimize.py` 的对应输出；位次换算和预测来自 `rank.py`，学费、计划数等事实来自官方资料。逐项注明来源，不把数据事实冒充优化结果；敏感性表要实际重算。
- 报告末尾附"追问清单"：读者大多看不懂全部细节，所以按这位考生的具体情况预备追问清单，比如他在犹豫的两个方向、差一点够上的志愿、和家人的分歧、换参数会怎样。不要放对谁都适用的通用问题。
- 出稿前把每一页渲染成图片检查版面。

字段、写作规矩和检查清单见 [report-guide.md](references/report-guide.md)，示例见 `examples/report_demo.json`。

## 常见误区（遇到就纠正）

- "冲的放后面、保的放前面更安全"——平行志愿下错。表内顺序应该按喜好从高到低；靠后放冲刺志愿等于白填。
- "分数够就一定能上"——还要看选科、体检、单科、语种、专业满额后是否服从调剂。
- "不服从调剂最多是去下一个志愿"——错。已经投档后被退档，通常直接掉出本批次，不会回到你的下一个志愿。
- "去年线低，今年就好捡漏"——大小年会均值回归，单年异常不可当趋势。
- "用分数比往年"——分数随试卷难度浮动，比较应当用位次（同科类、同首选科目）。
