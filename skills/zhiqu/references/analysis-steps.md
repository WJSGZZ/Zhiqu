# 分析步骤细则与计算工具

<!-- 核实：2026-10-07；复核期限：2027-07-01 -->

本文件是 `SKILL.md` 工作流第 3、4 步的完整细则和计算工具表，原样从 `SKILL.md` 移来（只改了相对路径），为的是让入口文件只留步骤索引与门槛。命令均在技能目录（`skills/zhiqu/`）执行。

## 第 3 步：核实本省规则与数据

当年填报模式（院校专业组 / 专业+院校 / 传统院校+专业）、每批次志愿个数、是否平行志愿、同分排序规则、投档比例；一分一段表；候选志愿近三年最低录取位次、今年招生计划与选科要求、招生章程中的体检/单科/语种/性别/调剂规则：考生不满足的志愿直接排除，满足但需复核的把原文写进候选 CSV 的 `limits` 列。**投档表只有院校专业组代码，不写组内专业**；每个组里有哪些专业，必须查当年招生计划或专业目录（高校本科招生网、省招生专业目录）。组号每年可能重排，跨年匹配一律按"学校 + 组内专业"对应，不按组号；对不上的年份宁可留空。一分一段表可能是扫描件，此时由 AI 看图读数，并用投档表中的"最低分 + 最低排位"交叉核对。专业组模式的省份，对最终候选里靠前的组，查招生章程的专业分配规则（分数优先、专业级差、志愿优先）和高校招生网的分专业录取位次，填进候选池的 `majors`、`rule` 列，让模型算出落到每个专业和被调剂的概率（见 [volunteer-game.md](volunteer-game.md)）。再看考生是否可能符合提前批、专项计划、定向培养、强基计划、综合评价等路径：多数考生不知道这些，要用大白话讲清是什么、要付出什么，按当年规则判断资格并给出建议，方法和三省回测结论见 [special-admissions.md](special-admissions.md)。再查近期报道：候选靠前的学校有没有更名、新校区、进出双一流，专业有没有停招、计划大增大减，行业有没有大的招聘或政策变化；这些常是录取线突变和前景变化的原因，处理方法见 [outlook.md](../../zhiqu-shared/references/outlook.md#联系报道社会情况怎样影响前景和录取线)。只用一手来源，出处和查询日期写进结果。数据来源清单见 [volunteer-game.md](volunteer-game.md#6-数据从哪来)。

## 第 4 步：换算位次、预测录取线、筛候选池

先用 `scripts/pool.py` 从本省历年投档数据生成候选宽表：它按教育部高校名单（`data/schools.csv`）补上院校所在省市和公办/民办（先确认明确校名与官方更名别名，招生代号不能覆盖不同学校的名称；匹配不到则保留未知），可按"留本省""只要公办"、位次范围筛选；专项、预科、民族班、少数民族、面向某地的定向、分校、中外合作等需要单独资格或学费不同的条目默认排除，考生符合资格时用 `--exclude` 放开。校名里的招生计划类括号（如“内蒙古大学(八协计划)”）不是校区：按括号外校名对教育部名单，对上就保留，并在 `limits` 列标“资格待核：计划名”，报告志愿表显示“需核对报名资格”，核实前不算保底；对不上名单的照旧剔除，`--screening-log` 记下条数和名单，供 `screening.json` 记账。院校代号每年重编的省份（河北）加 `--school name`。脚本提示有院校没匹配上时（多为 2025 年 6 月以后更名或新设的学校），这些条目的所在省要人工核对。专业组省份的投档表没有组内专业和选科要求，要对粗筛后的学校逐校查招生网的分组计划和分专业录取（常以图片发布，由 AI 读图并与投档表的组线核对）。**专业组跨年不再自动按组号拼接**：`pool.py --key group` 默认只用最近一年；核实组内专业、选科、校区、办学类型和招生路径后，通过 `--group-map` 提供一对一对应及官方来源，格式见 [volunteer-game.md](volunteer-game.md#候选池的跨年专业组对应)。拆组、合组或不明确的历史留空。可用 [目录相似度工具](group-matching.md) 辅助核对；建议必须经过人工确认才能导出映射。`--public` 会排除办学性质未知的条目，人工查清后再纳入。然后用 `scripts/rank.py`（见下文"计算工具"）：只有分数时先换算位次；还没出分就用 `estimate` 得到位次区间；把收集到的志愿历年位次写成 CSV，用 `predict` 算出每个志愿今年的预测位次、分数线和单独过线概率，筛掉几乎不可能（如 < 2%）的冲刺项。脚本对历年位次跳变超过约 40% 的组给出警告：先查章程和专业组组成找原因，查不清的不要当作捡漏机会。

   **目标专业够不上时补相近条目。** 方向确定后，对目标专业位次够不上的学校，检索同专业类、同学院的相近专业，以及包含目标专业的大类和试验班（按专业名筛选常漏掉它们）。补进的每一条核对三件事：核心课重合度（看培养方案）；去向门槛是否相同（考公专业目录、执业资格）；大类和试验班的分流范围与规则（以当年章程或专业目录为准，写进 `limits`，按调剂效用估“分流后最差可接受结果”）。

   **候选池比算法更重要。** 志愿位多的省份（≥ 30 个，如广东 45 个）几乎能把所有合理候选都填进去，结果主要取决于池子里有什么。资料充足时以志愿位的 2 倍作为候选池目标；符合硬约束的候选不足时如实说明，不为凑数加入未知资格或不愿就读的条目。并确保过线概率 40–85% 这一段有足够多的可选项；志愿位少的省份，组合选择才是主要价值所在。

## 计算工具

**凡是数字都用脚本算，不心算、不估读表格。** AI 负责找数据、做判断、解释结果；脚本负责确定性的计算。`rank.py` 与 `optimize.py` 只依赖 Python 标准库，共用同一套位次模型。

| 要做的事 | 命令 |
|---|---|
| 分数 → 位次 | `python3 scripts/rank.py score --table 一分一段.csv 596` |
| 位次 → 分数 | `python3 scripts/rank.py rank --table 一分一段.csv 23500` |
| 等位分（今年的分在往年相当于多少） | `python3 scripts/rank.py equiv --table 今年.csv --past 去年.csv --past 前年.csv 596` |
| 出分前：估分 → 位次区间 | `python3 scripts/rank.py estimate --table 去年.csv 596 --err 8` |
| 从本省历年投档数据生成候选宽表 | `python3 scripts/pool.py --year 2025=data/guangdong/physics_2025.csv ... --key group --in-province 广东省 --public --rank-min 15000 --rank-max 60000 --out 志愿.csv` |
| 预测各志愿今年录取线、过线概率，筛候选池 | `python3 scripts/rank.py predict 志愿.csv --rank 23500 [--table 今年.csv] --min-p 0.02 --out 候选池.csv` |
| 逐年回测：整体漂移、误差大小、结构突变、计划弹性；三年以上还比较预测方法、检验大小年 | `python3 scripts/backtest.py --key major --year 2025=data/zhejiang/general_2025.csv --year 2026=data/zhejiang/general_2026.csv …`（院校专业组模式用 `--key group`；院校代号每年重编加 `--school name`；只有分数时加 `--metric score`） |
| 选出期望效用最高的志愿表 | `python3 scripts/optimize.py 候选池.csv --rank 23500 --slots 45 --u-fall -60 [--max-fall 0.01]` |

- 一分一段表 CSV：`score` 列，加 `count`（该分人数）或 `cumulative`（累计人数）列。位次取该分的累计人数，与多数省份公布口径一致。
- 维护：`python3 -m unittest discover -s tests` 跑全部自动测试；`python3 scripts/validate_data.py` 校验数据；每年更新数据的步骤见 [data/README.md](../data/README.md)。
- 志愿 CSV 的列说明见 [volunteer-game.md](volunteer-game.md#3-csv-列说明)；示例在 `examples/candidates_demo.csv`（虚构）。`predict` 不需要 `utility` 列，输出的候选池保留原列并追加预测结果，补上效用即可交给 `optimize.py`。
- 出分前优化时，把 `estimate` 给出的 `--rank-sd` 传给 `optimize.py`，它会把考生自己位次的不确定性一起模拟。
- 考生总数变化明显时，`predict` 和 `optimize.py` 都可加 `--cohort 年份=人数 … --cohort-now 人数`，把历年位次按百分位折算到今年；与不折算的结果对照着看，因为人数增长未必均匀分布在各分数段。**不可与非零 `--drift` 同时使用，脚本会拒绝；`--cohort` 与 `--cohort-now` 必须成对提供，人数须为正数**：回测估出的漂移已经包含了考生人数变化的影响，两者叠加会重复计算。
- 招生计划数不要机械地折算进预测：广东 2022→2023 回测中，计划翻倍平均只让位次放松约 1%（见 [backtests.md](backtests.md)）。
- `data/` 已有 10 个省份的官方投档数据（广东、浙江、山东、河北、辽宁、江苏、湖北、湖南、上海、黑龙江），可直接用于回测和查历年线；各目录 README 写明来源与口径（有的位次为推算值、有的为 OCR 数据）。
- 先读 [backtests.md](backtests.md) 的本省记录和 [年度研究输出](../data/calibration/README.md)。历史建议不是当年的确定参数；只在同省、同科类、同批次且跨年匹配可信时使用。专业组按组号的研究结果不能当正式校准证据；缺数据的省份不借广东或其他省的倍数充当校准。参数尚未验证时做明确标注的敏感性分析，不把模型概率解释为已校准录取率。
- 等位分默认按位次对齐；两年同科类考生总数差别明显时，再用 `--by percentile` 对照一次，两者差得多就在报告里说明。

## 补充（2026-10-07，个案流程新增，不属于上面搬迁的原文）

- `pool.py` 新增 `--match-major`、`--exclude-major`（只看专业名，不含校名；`--match` 会连校名一起匹配，如“信息工程”命中南京信息工程大学的全部专业）和 `--in-provinces`（多个省市，逗号分隔）；输出多了 `major_code` 列，填报单用。
- `pool.py` 对校名带校区括号、而教育部名单只有主校区的条目（如“华北电力大学(保定)”被并入北京），在 `note` 列写“校区括号与名单所在地不符，所在地须人工核对”；按所在地筛选时必须逐项核对这些条目。
- 招生计划类括号（2026-10-22）：八协计划、协作计划、各类专项、预科、民族班、少数民族、定向、面向某地，按数据里实际出现的写法识别（`pool.PLAN_BRACKET`）；卓越优才计划、中高计划、京津冀职教改革项目等含义未核实，仍按校区括号处理。以前八协计划被当成校区、因“与所在地不符”在回溯流程中剔除；已登记的 R01—R12 在 `retro_config.json` 写 `"plan_bracket_rule": "legacy"` 保留登记时的结果，新案例默认用新规则。保底若只靠“资格待核”志愿撑着，`check_report` 要求在 `meta.floor_shortfall` 写原因与补救，并在正文写明须核对报名资格。走 `pipeline.py` 时，偏好表只有在该条 `eligibility_evidence` 为 verified 时才能取代“资格待核”标记。
- `scripts/category_shift.py`：看相邻两年某一类专业的整体位次变化（中位数与变难占比），用来发现全省漂移之外的类别共同变动；只描述，不改预测。
- 每一单的取数、筛选账和门槛见 [case-workflow.md](case-workflow.md)，省份层规则文件样例见 `../data/zhejiang/rules.json`。
