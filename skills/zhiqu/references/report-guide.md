# 决策报告：怎样写、怎样出稿

最终交付物是一份 PDF 决策报告。所有结论、表格、假设、待办和声明都要写进报告，不能只留在对话里。报告的标准是专业机构的商业报告：先给结论，再给证据；每个数字都有来源；版面克制、易读，不堆文字。

## 生成

```bash
python3 scripts/optimize.py 候选池.csv --rank <位次> --slots <志愿数> --u-fall <滑档效用> --json result.json
python3 scripts/report.py report.json --opt result.json --out <报告号>-report.pdf --profile-version profile.txt
```

`report.py` 用本机的 Chrome 或 Edge 打印 PDF（宣纸底色、A4、带页眉页码）。找不到浏览器时会输出 HTML，用浏览器"打印 → 存储为 PDF"，并勾选"背景图形"。工具字段输入见 `examples/report_demo.json`（只作HTML预览）；交付示例以案例目录为准，须有 `case.json` 并明确选定画像版本。PDF附核对材料和数据附件，离线核对及联网复核的方法见仓库 `AGENTS.md` 的「如何只凭一份报告核对」。

## 写作规矩

- **前面给普通人看，后面才给专业读者看。** 封面的一句话结论、摘要、画像、方向、志愿表只用大白话，不出现"期望效用""蒙特卡洛""对数正态"这类词。必须提到时，先用一句大白话解释。专业术语集中放在"方法与假设"一节，并在末尾的术语表里解释。**正文给人读，核对给第 12 节**：参数表、模型细节、六个方法小节、逐志愿历年位次、院校调研原文、逐项核对材料和来源列表都放在第 12 节“核对与来源”，正文只留读者做决定需要的结论和图。
- **每个数字都来自计算结果。** 报告里的概率、期望、位次，必须和 `optimize.py` 的输出一致；写完后逐条对照 `result.json` 核对。不要凭印象写"八成把握""冲两个稳两个"。标签（冲/稳/保）、最可能的去向、滑档概率，都以输出为准。
- **敏感性表要实际算。** 改 `--rho`、`--u-fall` 等参数重新运行，填入真实结果；不要估计。
- **结论先行，一段一个意思。** 摘要要点控制在 3–5 条，每条一句话讲清"是什么、为什么"。
- **给考生留下行动。** "接下来你要做的事"不超过 3 条，要具体到去哪里查、问谁。
- **追问清单要个性化。** 从这份报告里找出考生最可能卡住或最在意的地方：画像里的矛盾、两个方向怎么选、差一点够上的志愿、家人的不同意见、某个参数换了会怎样。每条问题用考生自己的口吻写，后面附一句"为什么值得问"。6–10 条，分 2–4 组。
- **前景写成有条件的判断，并实际算一次悲观情景。** 方向卡片的 `outlook` 写明前提和前提不成立时的后果（方法见 [outlook.md](../../zhiqu-shared/references/outlook.md)）；把受影响方向的效用按悲观情景下调后重跑，敏感性表里同时给出"按原表填、结果悲观"和"按悲观情景重排"两个数，差距就是押错方向的代价。
- **硬性限制先排除，再写提醒。** 从当年招生章程查体检（色弱、视力、身高）、单科成绩、外语语种、性别等限制；考生不满足的志愿直接从候选池删除，不是打低分；满足但需要复核的，把原文写进候选 CSV 的 `limits` 列，报告会在志愿表和填报单上标红提醒。
- **志愿位没填满时不强制补满。** 优化器在压力补位后仍没填满（“再加任何一个都没有增益”），报告写明原因，并给固定做法：可以在已选志愿之后补，**只补本人确认“录了也愿意去”的候选**，按满意度从高到低排；不愿意去的宁可空着。理由写给考生：平行志愿下后补的志愿不影响前面志愿的检索顺序；被录到不想去的学校，可能比滑档后走征求志愿、下一批次或复读更糟，这要本人和家人判断。补进的志愿同样要过资格与章程核对，并在填报单上列出。
- **不确定的写成不确定。** 推算值、OCR 数据、单人说法、未核实的原因，都在对应位置注明。

## report.json 字段

| 字段 | 内容 | 出现在 |
|---|---|---|
| `meta` | `title` `subtitle` `candidate` `province` `category` `batch` `score` `rank` `date` `slots`，付费报告另加 `case_id`（报告编号）与 `generated_on`（生成日期，YYYY-MM-DD），印在封面和页眉 | 封面、页眉 |
| `summary.headline` | 一句话结论（大白话，含最可能的去向和滑档风险） | 封面、摘要 |
| `summary.points` | 3–5 条核心结论 | 摘要 |
| `summary.actions` | 最多 3 条待办 | 摘要 |
| `profile.intro` / `facts` / `priorities` / `constraints` / `tensions` | 画像要点、权重（小数）、硬约束、需要考生想清楚的矛盾 | 你的画像 |
| `directions` | 每个方向：`name` `fit` `majors` `evidence` `counter` `outlook` `verify`；`outlook` 是若干条"若……则……；若不成立……"的前景判断；`paths` 是 `[去向, 门槛, 代价, 依据]` 行，覆盖考研、考公、就业（生涯规划融在这里，不单独成块） | 专业方向 |
| `roadmap` | `[核对项, 安排]` 五行：门槛与差距、顺序与投入、里程碑与截止、切换条件与备选、下次检查点 | 专业方向（末尾） |
| `list_notes` | 志愿名 → 一句话说明（为什么在这一格）；过线概率偏低的专业组志愿，再写一句“若刚过组线，最可能落到哪个专业，它在不在你的可接受名单”（组内专业不全时写“组内专业不全，待核”） | 志愿表 |
| `why` / `stress_mult` / `sensitivity` | 排序理由段落、压力倍数、敏感性表 `[假设, 期望效用, 滑档概率, 前段是否变化]` | 为什么这样排 |
| `research` / `questions` | 院校调研 `[{school, items: [[方面, 发现, 证据等级]], sources: [https 链接], brief: {方面: 一句结论}}]`（写了 `brief` 的学校在正文显示为卡片，每个方面一句话，原文表移到第 12 节；`brief` 只能概括“发现”里已有的事实，不新增数字或判断，没取到就写没取到）；请考生亲自去问学长学姐的问题 | 院校调研 |
| `todo` | `[事项, 去哪里查]` | 核对清单 |
| `meta.prob_grade` / `meta.grade_note` / `meta.reform_year` | 本报告采用的概率评级（A—D）、理由、是否改版年；见下文“按本省评级写概率” | 封面不显示，方法一节自动写明 |
| `assumptions` / `backtest` | `[参数, 取值, 依据]`；本省回测结论 | 方法与假设 |
| `methods` | 小节列表，每节 `title` `paras`，可选 `columns` `rows` `notes`；付费报告须含数据、模型、参数、不确定性、局限、证据等级六个小节（标题含这些词），写法见下文“方法一节的写法” | 方法与假设 |
| `ask_me` | 个性化追问清单：`[{topic, items: [{q, why}]}]`，`q` 用考生的口吻写 | "追问清单"一节 |
| `hindsight` | 仅回测案例：`intro` `columns` `table` `notes`，可选 `extra`（与 `methods` 同样的小节），对照真实结果 | "事后回看"一节 |
| `omitted` | 某节没有内容的原因，如 `{"research": "候选尚未收窄，院校调研留到确定前 10 个志愿后再做"}` | 对应节 |
| `news` | `[事件, 日期, 来源, 对本报告的影响]`：影响前景或录取线的近期报道与政策 | 专业方向（末尾表格） |
| （填报单） | 自动生成：院校代码、专业组或专业代码取自候选 CSV 的 `code`、`group`、`major_code` 列，组内专业顺序取自 `majors` 列；没有代码的留空待填 | 填报单 |
| `sources` | `[数据, 来源, 查询日期]` | 核对与来源 |

**目录固定**，每份报告都是下面 12 节，顺序和编号不变，方便考生、家长和不同报告之间对照：

01 摘要 · 02 你的画像 · 03 专业方向 · 04 志愿表 · 05 为什么这样排 · 06 院校调研 · 07 填报前核对清单 · 08 填报单 · 09 追问清单 · 10 方法与假设 · 11 事后回看 · 12 核对与来源

**第 08 节**：填报单。行动路线（门槛、顺序、里程碑、切换条件、检查点）并入第 03 节末尾的 `roadmap`。知衢不单独出“出分前”的报告：出分前只做方向的确定，写进完整版的第 03 节，出分后再排志愿表。

某一节确实没有内容时，不删节，在 `omitted` 里写明原因（键为 `directions` `list` `research` `todo` `ask_me` `hindsight`），报告会在该节显示这句说明；没写原因时 `report.py` 会在终端提醒。"事后回看"在事前报告里默认提示考生放榜后回来对照。

## 付费报告的必备内容与篇幅（由 `check_report.py` 的 `check_sections` 检查）

目的：每份报告密度相近，不因分析者当天状态而厚薄不一。下限是“有、够、能溯源”，不是越长越好；写得好不好由复核判断。

| 节 | 必备 | 下限 |
|---|---|---|
| 01 摘要 | 一句话结论、核心结论、待办 | 结论句 ≥ 20 字；核心结论 3–5 条；待办 1–3 条 |
| 02 你的画像 | 事实表、权重、硬约束、矛盾 | 事实 ≥ 8 行；权重 ≥ 4 项且和为 1；硬约束 ≥ 3；矛盾 ≥ 1 |
| 03 专业方向 | 2–4 个方向，每个有支持、反面、前景、验证、去向；末尾路线图与近期报道 | 支持 ≥ 2、反面 ≥ 1；前景 ≥ 2 条且都是“若……则……”；`paths` 覆盖考研/考公/就业且四格齐全；`roadmap` 五行；报道 ≥ 2 条 |
| 04 志愿表 | 全部志愿及说明 | `list_notes` 至少覆盖 max(10, 志愿数/4) 个，名称须在志愿表内 |
| 05 为什么这样排 | 排序理由、压力测试、敏感性 | 理由 ≥ 3 段；敏感性 ≥ 3 行且含前景悲观情景（须实际重算） |
| 06 院校调研 | 最可能去的几所，逐条附来源 | ≥ 3 所；≥ 3 所各覆盖培养方案、转专业、收费、校区、就业质量中 ≥ 4 项有证据的内容（取不到的写“未取到”，不计入）；每所 ≥ 2 条 https 来源；每条发现标证据等级；学长学姐问题 ≥ 5 条 |
| 07 填报前核对清单 | 待核事项与去哪里查 | ≥ 5 行 |
| 08 填报单 | 与 `result.json` 一致的录入表 | 无空代码（`report.py --sheet` 同时导出 CSV） |
| 09 追问清单 | 个性化追问 | 2–4 组、共 6–10 条 |
| 10 方法与假设 | 正文：概率能信到什么程度、往年检验、术语解释；参数、依据和六个小节（数据、模型、参数、不确定性、局限、证据等级）印在第 12 节“方法细节” | 参数 ≥ 6 行；有回测结论；六个小节齐全；证据等级表 ≥ 4 行，等级只用四档 |
| 11 事后回看 | 放榜后对照 | 事前报告可用 `omitted.hindsight` |
| 12 核对与来源 | 声明、方法细节、院校调研原文、逐项核对材料、来源与日期 | ≥ 8 行，每行 `[数据, 来源, YYYY-MM-DD]` |

除“事后回看”外，付费报告不得用 `omitted` 省略章节。个案目录、阶段门槛与复核见 [case-workflow.md](case-workflow.md)。

## 方法一节的写法（科研级的严谨）

作者要求报告更详细、更专业，达到科研级的严谨，结论清晰且正确。前几节仍用大白话；严谨性集中体现在“方法与假设”的六个小节里（印在第 12 节“方法细节”），专业读者能据此复现和挑错：

1. **数据与口径**：用了哪些表、哪些年份、多少条、怎样匹配跨年条目、哪些条目因缺失或重复被剔除；来源等级（官方原表、识别、推算）。
2. **模型设定**：录取线的分布假设、均值与波动怎样估计、共同波动怎样处理、优化目标与约束；写成可复现的式子或步骤，不只写名字。
3. **参数选择与样本外证据**：每个参数怎么选、只用了哪些年份、在留出年份上的覆盖率或误差；没有样本外证据的参数明说。
4. **不确定性与校准**：概率的含义（统计外推，不是录取率）、区间宽度、已知的系统偏差（如方向共同变热）以及敏感性结果说明了什么。
5. **局限与效度威胁**：没建模的机制（退档、体检、同分、组内调剂等）、数据缺口、样本量、可能让结论翻转的条件。
6. **结论与证据等级**：把报告的主要结论逐条列出，`[结论, 依据, 等级]`，等级只用“已证实、有证据待确认、目前无证据、不可能或极不可能”四档；摘要里的结论不能比这里的等级更强。

## 按本省评级写概率

每省每科类的可信度评级只记在 [年度校准目录](../data/calibration/README.md#十省可信度体检2026-10-16)。出稿前查本省评级，写进 `meta`：`prob_grade`（本报告实际采用的评级，A—D）、`grade_note`（本省评级、是否改版年、为什么用这一档），改版年另写 `reform_year: true`。`report.py` 按 `prob_grade` 自动处理志愿表、摘要卡片和图上的概率；正文（第 01—09 节）里作者写的概率由 `check_report.py` 检查。第 10、11 节面向专业读者，可以保留模型原始数值。

| 评级 | 报告怎么写概率 | 保底要求（`check_report.py` 用 `result.json` 检查） |
|---|---|---|
| A | 可以写百分比，仍注明“按历年波动推算，不是录取率” | 至少一个志愿单独过线 ≥ 95% |
| B | 百分比取整到 5%（如“约 15%”），同时写 80% 区间 | 至少一个志愿单独过线 ≥ 99%，且预测线比本人位次宽 20% 以上 |
| C | 不写百分比，只写冲、稳、保三档和预测区间；第 10 节说明为什么 | 至少两个志愿的预测线比本人位次宽 30% 以上 |
| D | 不出过线概率，只按公开资料做定性分析；用内部未核数据时逐条标明 | 人工按历年线留足余量，并写进核对清单 |

数据薄的省份（山西 C、河南 D）另按 [backtests.md「数据薄的省份怎么做」](backtests.md#数据薄的省份怎么做山西河南2026-10-17-检验)：保底组须组内专业都能接受并服从调剂；新设组、只有一年历史的组、旧高考位置提示会收紧的组不作唯一保底；旧高考位次只写方向并标来源等级。

改版年（选考要求、志愿个数或批次调整的当年）在本省评级基础上降一档；`prob_grade` 不能比本省评级更乐观。方向集中的志愿表（一半以上志愿属于同一专业方向）必须做“该方向整体变热”的敏感性情景，幅度取本省该方向历年相对变化的最大值。

## 出稿前检查

1. 把 PDF 每一页渲染成图片逐页看：封面是否满版、有没有孤立的标题、表格有没有被截断、图表是否清晰。
2. 对照 `result.json` 核对摘要和志愿表里的每个数字。
3. 通读前四节，确认没有未解释的术语。
4. 确认"核对与来源"一节的来源和日期完整。

## 一条命令重现完整流程

先核实资格与偏好，再运行程序。`pipeline.py` 不替考生打分：它先用 `pool.py` 生成宽表，只保留偏好 CSV 中人工确认的 `id`，合并效用/约束/组内分配参数，再依次调用 `rank.py predict`、`optimize.py` 和 `report.py`。偏好表不能覆盖历史位次、院校代码、名称、选科或招生计划；旧 `id`、重复 `id` 与缺少效用的条目会报错。

在技能目录执行纯虚构演示：

```bash
python3 scripts/pipeline.py examples/pipeline_demo/config.json --out-dir /tmp/zhiqu-pipeline-demo
```

输出目录必须为空，以免覆盖已有报告。生成 `pool.csv`、`reviewed.csv`、`predicted.csv`、`result.json` 与已核验的 `report.html`。配置的 `pdf` 设为 `true` 时再输出 PDF；需要本机浏览器。配置各输入路径相对配置文件目录解析，输出目录相对执行目录解析。

配置的 `pool`、`predict`、`optimize` 是相应脚本的参数名与取值（参数名不带 `--`，可重复参数用数组）；`shared` 统一传递位次、漂移、考生人数、目标年、波动参数，禁止在某一步单独覆盖。`preferences` 是人工确认的偏好表，`report` 是报告内容 JSON。允许的偏好字段为 `id`、`utility`、`adj`、`p_adjust`、`utility_adjusted`、`obey`、`majors`、`majors_complete`、`rule`、`gap`、`limits`。凡填写 `majors`，必须显式填写 `majors_complete=0`（部分目录）或 `1`（已核实完整）；不允许沿用默认值。流程不增加录取规则；不得启用未经该省留出年验证的规则。

演示使用由 `candidates_demo.csv` 转换的虚构投档表，没有真实学校、考生或官方资格。候选输入次序会影响固定种子下的有限模拟结果，因此一键流程的数值不承诺和直接运行原候选 CSV 完全相同；报告必须对应本次生成的 `result.json`。

## 自动核验报告数字

`report.py --opt` 在生成前自动检查封面位次、志愿位数、压力倍数与显式数字声明。生成 PDF 后还会自动做版面自检（[check_layout.py](../scripts/check_layout.py)：表格某栏被挤成一字一行、数字被拆成两行、中文被挤成窄条），没通过就报错退出，不能交付。可另外核验 HTML 的摘要指标和整张志愿表：

```bash
python3 scripts/check_report.py report.json --opt result.json --html report.html
```

HTML 核验覆盖推荐数量、最可能去向及概率、满意度指标、基准与压力滑档风险，以及逐行顺序、志愿名、标签、效用、过线概率、落点概率和预测位次。检查不通过时退出码为 1；HTML 中的数字按实际显示精度对照。

自然语言数字须显式登记，程序不会猜“八成把握”说的是过线、落点还是满意度。例如摘要第二条文字为“平均满意度 76.4 分”，其数值来自同一次优化输出，可在 `report.json` 增加：

```json
"numeric_claims": [
  {
    "report_path": "summary.points.1",
    "number_index": 0,
    "result_path": "expected_utility",
    "tolerance": 0.05
  }
]
```

路径用点号连接，数组下标从 0 开始；`number_index` 表示这段文字中的第几个数字。概率写成百分数时增加 `"scale": 100`，如显示到一位小数，容差可取 `0.05` 个百分点。若自然语言有年份、章节编号等其他数字，必须核准下标。未登记的正文、不同重算结果对应的敏感性表、官方事实和 PDF 排版仍须人工复核，不能把“自动通过”写成全报告已经审计。

## 统一呈现与术语

三版的封面、字体、宣纸底色、石绿/琥珀色板、组件及打印规范统一由`../scripts/report.py`定义。固定六格封面依次为对象、版本或阶段、地区或学校、报告编号、生成日期、数据截至；每格最多两行，长说明移入摘要。姓名仅在封面与页眉加“（模拟）”；正文按正式决策报告写，不放开发说明。页眉带版本与编号，页脚显示页码/总页数。

每节先给一句加粗结论，再列依据；小标题最多两级。正文字号10pt、行距1.75，最小字号7pt；数字用千分位、数字与中文单位留空格，区间用“—”，概率精度沿用本省评级规则。图表必须有标题、读图说明和来源编号；完整网址集中在第12节，正文只放尾注编号。生成时会拒绝缺标题/来源编号的SVG和正文长网址，PDF必须通过版面检查并逐页审看。

| 统一叫法 | 含义 | 不再混用的写法 |
|---|---|---|
| 单独过线 | 不考虑前序志愿时，该志愿达到投档位次条件的可能性 | 过线概率、预测过线 |
| 最终录取 | 考虑志愿顺序后，落到该志愿的可能性；章程与退档条件仍须另核 | 落点概率、录取率 |
| 预测位次 | 目标年最低录取位次的中位预测，区间另标置信范围 | 预测线 |
| 期望效用 | 各可能结局按概率加权的偏好分，正文首次提及时解释为平均满意度 | 收益、性价比 |
| 初试分数情景 | 条件假设或有来源的本人练习分数，与历史群体分布对照 | 个人上岸概率 |
| 到手年收入 | 扣个人社保、公积金与个税后的现金，公积金账户单列 | 税前年薪、含公积金收入 |
| 每小时到手收入 | 到手现金除以写明口径的全年工作小时 | 未注明口径的时薪 |
| 月结余 | 全年到手现金按月平均后，扣住房及其他支出；普通月份另说明 | 到手月薪、收入 |

高考志愿主表固定七栏：序、志愿、类型、偏好、单独过线、最终录取、预测位次。历年位次、计划和组内补充明细集中在第 12 节“方法细节”末尾的“各志愿历年位次与计划”；主表一行灰字只提示关键事项。C/D级仍显示七栏，但不填精确百分比；不得为了图表恢复被评级禁止的概率。

读研、求职的Markdown组件及来源尾注写法见`../scripts/render_report.py`顶部说明。区间点图缺数据时明确“未取到”，不画假零值；比较矩阵用✓/△/✗分别表示已支持、待核/有条件、已不符，不能只凭样式替本人下结论。路线卡固定门槛、时间窗口、投入、切换条件四栏。新增计算须写入对应calculations并能由检查程序重算。

高考[内容合同清单](report-contract.json)只登记既有12节及落点条、单独过线图、方向矩阵，数量和概率权限仍由现有 check_sections / check_grade 决定；不替换原门槛。C/D级单独过线只允许分档/区间说明，不绘精确概率条。操控者核查与共用评分见[工作流总纲](../../zhiqu-shared/references/report-workflow.md)。
