# 决策报告：怎样写、怎样出稿

最终交付物是一份 PDF 决策报告。所有结论、表格、假设、待办和声明都要写进报告，不能只留在对话里。报告的标准是专业机构的商业报告：先给结论，再给证据；每个数字都有来源；版面克制、易读，不堆文字。

## 生成

```bash
python3 scripts/optimize.py 候选池.csv --rank <位次> --slots <志愿数> --u-fall <滑档效用> --json result.json
python3 scripts/report.py report.json --opt result.json --out 志愿填报决策报告.pdf
```

`report.py` 用本机的 Chrome 或 Edge 打印 PDF（浅黄底、黑字、A4、带页眉页码）。找不到浏览器时会输出 HTML，用浏览器"打印 → 存储为 PDF"，并勾选"背景图形"。完整示例见 `examples/report_demo.json`。

## 写作规矩

- **前面给普通人看，后面才给专业读者看。** 封面的一句话结论、第 01 节摘要、第 02–04 节只用大白话，不出现"期望效用""蒙特卡洛""对数正态"这类词。必须提到时，先用一句大白话解释。专业术语集中放在第 08 节"方法与假设"，并在末尾的术语表里解释。
- **每个数字都来自计算结果。** 报告里的概率、期望、位次，必须和 `optimize.py` 的输出一致；写完后逐条对照 `result.json` 核对。不要凭印象写"八成把握""冲两个稳两个"。标签（冲/稳/保）、最可能的去向、滑档概率，都以输出为准。
- **敏感性表要实际算。** 改 `--rho`、`--u-fall` 等参数重新运行，填入真实结果；不要估计。
- **结论先行，一段一个意思。** 摘要要点控制在 3–5 条，每条一句话讲清"是什么、为什么"。
- **给考生留下行动。** "接下来你要做的事"不超过 3 条，要具体到去哪里查、问谁。
- **不确定的写成不确定。** 推算值、OCR 数据、单人说法、未核实的原因，都在对应位置注明。

## report.json 字段

| 字段 | 内容 | 出现在 |
|---|---|---|
| `meta` | `title` `subtitle` `candidate` `province` `category` `batch` `score` `rank` `date` `slots` | 封面、页眉 |
| `summary.headline` | 一句话结论（大白话，含最可能的去向和滑档风险） | 封面、摘要 |
| `summary.points` | 3–5 条核心结论 | 摘要 |
| `summary.actions` | 最多 3 条待办 | 摘要 |
| `profile.intro` / `facts` / `priorities` / `constraints` / `tensions` | 画像要点、权重（小数）、硬约束、需要考生想清楚的矛盾 | 第 02 节 |
| `directions` | 每个方向：`name` `fit` `majors` `evidence` `counter` `verify` | 第 03 节 |
| `list_notes` | 志愿名 → 一句话说明（为什么在这一格） | 第 04 节 |
| `why` / `stress_mult` / `sensitivity` | 排序理由段落、压力倍数、敏感性表 `[假设, 期望效用, 滑档概率, 前段是否变化]` | 第 05 节 |
| `research` / `questions` | 院校调研 `[方面, 发现, 证据等级]`；请考生亲自去问学长学姐的问题 | 第 06 节 |
| `todo` | `[事项, 去哪里查]` | 第 07 节 |
| `assumptions` / `backtest` | `[参数, 取值, 依据]`；本省回测结论 | 第 08 节 |
| `sources` | `[数据, 来源, 查询日期]` | 第 09 节 |

没有内容的字段可以省略，对应的节会自动跳过（摘要、方法、来源与声明始终保留）。

## 出稿前检查

1. 把 PDF 每一页渲染成图片逐页看：封面是否满版、有没有孤立的标题、表格有没有被截断、图表是否清晰。
2. 对照 `result.json` 核对摘要和志愿表里的每个数字。
3. 通读前四节，确认没有未解释的术语。
4. 确认第 09 节的来源和日期完整。
